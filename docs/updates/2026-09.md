## U-20260922-03 · 2026-09-22 · Contain per-source, per-paper and write failures · #done #robustness

- **What**: one bad source, paper or file no longer throws away the rest of a run. `pipeline._safe_search` treats any unexpected exception from a source plugin (for example a `KeyError` after an upstream schema change) like a `FetchError`: that source returns nothing and the others keep their results. `download_pdfs` and `resolve_oa_pdfs` gather with `return_exceptions=True`; a failed download becomes a skipped result with reason `error_<ExceptionType>`, and a failed OA lookup keeps the paper without a `pdf_url`. `export_collection` turns an `OSError` on write (for example the previous `.xlsx` still open in Excel) into an `ExportError` that says what to do. The pptx exporter names the `PaperSummary` field whose shape broke a rich slide builder and pads ragged table rows instead of raising `IndexError`. The xlsx exporter strips control characters openpyxl refuses. `review_deck` raises `ExportError` for a missing or non-pptx file, and `review` keeps reporting the other decks when one path is unreadable. Part of `progress.md` #1.

## U-20260924-02 · 2026-09-24 · Release runs only for pushes here; least-privilege workflow permissions · #ci #security

- **What**: a scan with zizmor 1.30.1 (`zizmor --offline .github/workflows`) found three things in the release path, fixed here:
  - **Fork pull requests could start a release.** `release.yml` runs on `workflow_run` of CI with `branches: [main]`, but that filter compares the head branch *name*: a pull request from a fork's own `main` into `main` also completes CI "on main". `bump-version` checked only `conclusion == 'success'`. Only pushes to this repository release.

## U-20260925-01 · 2026-09-25 · Nuitka release build actually uses its compiler cache; cap raised to 120 min · #ci #release #fix

- **What**: the `build-nuitka` job cached `~/.nuitka`, `~/.cache/Nuitka`, `thesisagents.build` and `thesisagents.dist`, but on Windows Nuitka keeps its compiler cache (clcache) and downloads under `%LOCALAPPDATA%\Nuitka\Nuitka\Cache` (`nuitka/utils/AppDirs.py` in Nuitka 4.2.2: `NUITKA_CACHE_DIR`, else `appdirs.user_cache_dir`). The cache step restored and saved ~188 MB every release, yet the 2026-09-25 log reads `Compiled 2738 C files using clcache with 0 cache hits and 2738 cache misses` and re-downloads `depends.exe`. Every release was a cold build.
  - The job now sets `NUITKA_CACHE_DIR: ~/nuitka-cache` and caches only that directory. Nuitka and `actions/cache` both expand `~` to the runner's home. The build and dist folders are no longer cached: restoring the build folder did not save any compile, and a restored dist folder could carry a stale file into the release zip.
  - `timeout-minutes` 90 → 120. The Nuitka step took 88, 86, 82 and 86 min in the releases of 2026-09-23 to 2026-09-25 (58–72 min before that), so the next slower runner would have timed out and left the release as a draft. A cold build still happens whenever the cache is missing, since GitHub evicts caches unused for 7 days.
  - Docs: `docs/releases.md` (timings table, cap), `docs/troubleshooting.md` (timeout entry, how to spot `0 cache hits`), `docs/packaging-nuitka.md` (where the cache lives, both CI snippets). The cold build time in `README.md` and the 13 translations goes from ~50–70 / ~70 min to the measured ~80–90 / ~85 min. The warm figure (~5–10 min) stays as the expected value until a release measures it (`progress.md` #5).
  - U-20260924-02 kept the cache-poisoning finding on these caches because they "bring a cold 50–70 minute PySide6 build down to minutes". That was not true at the time. The reasoning for keeping them still holds: a pull request cannot write into `main`'s cache scope, and the release installs the same dependencies from PyPI whether or not the cache is warm.
- **Tests**: `tests/test_workflow_actions.py` checks that `release.yml` sets `NUITKA_CACHE_DIR` and that the Nuitka cache step saves exactly that path. The previous workflow fails it. The step parser shared with the checkout test moved into `_steps_using(text, action)`.
- **Result / numbers**: pytest 690 passed, ruff clean, bandit no issues, `test_i18n` 38 passed.
- **Sources**: Nuitka job log of run 36112320707; Nuitka 4.2.2 sdist (`nuitka/utils/AppDirs.py`, `nuitka/build/SconsCaching.py`); job durations from `gh run view` over the last 12 releases.
