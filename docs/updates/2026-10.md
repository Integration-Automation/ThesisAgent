## U-20261008-02 · 2026-10-08 · Export verifies every DOI and URL before writing · #done #export #cli #mcp #gui

- **What**: roadmap PR #26 feature 1. `export_collection` now runs an identifier preflight before any exporter (`thesisagents/core/export_validation.py`). Strict by default: a wrong or unreachable DOI / URL raises `IdentifierVerificationError` (an `ExportError`) carrying the full report, and no file is written. `ExportOptions(verify_identifiers=False)` skips it and logs a warning.
  - **DOI**: syntax first with no network (`canonical_doi` in `core/identifiers.py`, which also accepts `doi:` and `https://doi.org/` spellings, percent-encoding and dotted sub-registrants), then the doi.org handle API `/api/handles/<doi>`. The lookup never touches the publisher's site.
  - **URL**: one streamed `GET` that reads only the headers. Redirects are followed by hand so a hop to plain `http` or to a browser-only publisher host is never requested. A URL on such a host (`fetchers/webrunner_pdf.py::should_use_webrunner`) is not requested either, the DOI lookup stands in for it. A plain-`http` URL is probed through its `https` form.
  - **Five statuses**: `ok`, `invalid` (malformed or unregistered DOI, URL 404 / 410), `unreachable` (DNS / connection failure, 5xx), `timeout`, `skipped` (`file://`, browser-only host, HTTP 401 / 403 / 429). `invalid`, `unreachable` and `timeout` block the export, the last two only after one retry. `skipped` never blocks.
  - **Bounded**: 5 probes in flight, 2 per host, 8 s per request.
  - **Cache**: `VerificationCache` protocol with `MemoryVerificationCache`. The CLI verifies once right after the search, before PDF download and enrichment, and passes the same cache to every later `export_collection` call.
  - **Never rewrites the record**: a redirect target or a DOI's registered landing page is reported as `resolved_url`, the paper's `doi` / `url` stay as supplied.
- **Surfaces**: CLI `--no-verify-identifiers` (the notice goes to stderr even under `--quiet`) and a one-line summary `Identifiers: N verified, M not checkable, 0 failed.`. MCP `export(verify_identifiers=true)` returns a `verification` block and fails with the list of identifiers as its error text. GUI Deck tab has a "Verify DOIs and URLs before export" checkbox, ticked by default.
- **Supporting changes**: `fetchers/http.py::scoped_client` (an HTTPS-only client outside the shared registry, for code on a private event loop) and `utils/async_helpers.py::run_blocking` (finish a coroutine from synchronous code, inside or outside a running loop). `export_collection` is synchronous and the CLI calls it from a coroutine.

## U-20261008-04 · 2026-10-08 · Every search reports what each source returned · #done #search #cli #mcp #gui

- **What**: roadmap PR #26 feature 3, `progress.md` #7. `run_search` keeps one outcome per source instead of flattening the results at once (`_fetch_all`, `_SourceOutcome` in `core/pipeline.py`) and records a `SourceStat` per source in `PaperCollection.diagnostics.source_stats`: `requested` (the per-source cap), `returned` (records sent back), `after_dedup` and `status` with the error text in `detail`.

  - The counts are taken before the `Query` filters and the `max_results` cut. Failure isolation is unchanged, and the papers a search returns are the same as before.

## U-20261008-06 · 2026-10-08 · A persistent SQLite literature library · #done #library #cli #mcp

- **What**: roadmap PR #26 feature 5, `progress.md` #9. New package `thesisagents/library/`.
  - `store.py`: `Library(path, create=True)` over one SQLite file. `add_collection` / `add_papers` merge an import and return an `AddReport` (`added`, `merged`, `relations_added`, `relations_skipped`, `total`). `search(query, limit, year_from, year_to)` returns `LibraryEntry` items (paper, first and last seen, times seen, sources, score), `collection(query)` the same papers as a `PaperCollection` for the exporters, plus `relations()`, `runs()`, `stats()` and `verification_cache()`.
  - `schema.py`: six tables (`papers`, `identity_keys`, `runs`, `observations`, `relations`, `verifications`), the version in `PRAGMA user_version` (now 1) and `PRAGMA application_id` marking the file. `prepare()` runs the migrations a file has not seen, each in one transaction with its version bump, and raises `LibraryError` for a newer version, another application's database, or a file that is not SQLite. Such a file is left untouched.
  - **Merge, never duplicate.** A paper is matched on every key of `Paper.identity_keys()` with the functions search de-duplication uses, now public in `core/dedup.py` as `fuzzy_link_allowed` and `merge_papers` (they were `_fuzzy_link_allowed` / `_merge`). A paper carrying the DOI of one stored paper and the arXiv ID of another joins the two, with their sightings and links. Same title with two different DOIs stays two papers.
  - **Provenance at two levels.** `observations` records which run saw a paper through which source, at what rank, with what score and pruning advice. The record keeps `Paper.provenance` for each backfilled field.
  - **One departure from "first value wins"**: a later, higher `citation_count` replaces the stored one, and its provenance entry is replaced, not appended.
  - **Verdict reuse.** `LibraryVerificationCache` implements `VerificationCache`. A verdict that lets an export through (`ok`, `skipped`) is reused for 30 days (`VERIFIED_FOR`). A failure is stored and never reused, so a timeout from an earlier run cannot keep failing an export. `Verdict.blocking` is new and names that distinction.
  - **Search** scores the stored papers with `rank_with_scores` and returns the ones matching at least one query term, so a library lookup reads a query the way a search does.
  - WAL journal, a 30 s busy timeout, every multi-row write in one `BEGIN IMMEDIATE` transaction, one lock-guarded connection per `Library`.
- **Surfaces**: CLI `--library PATH` (also the run's identifier cache), `--library-add`, and two modes that take the place of `--query`: `--library-search QUERY` and `--library-export [QUERY]`. A library export defaults to `xlsx,bib`, downloads no PDF unless `--export` includes `pdf`, and enriches nothing unless `--enrich` is given. MCP: `library_add`, `library_search`, `library_stats` (the server now lists 17 tools) and `export(library=...)`. No GUI control yet, see `progress.md` #14.
- **Caught while building it**: the first migration used `executescript`, which commits any open transaction first, so a migration that failed halfway would have left tables behind with no version, a file the next open would then refuse as "not a library". Statements now run one by one inside the transaction, and `test_a_migration_that_fails_leaves_the_previous_version` covers it. Stored "not checkable" verdicts were at first not reused, so those URLs would have been requested again on every run, which is why `skipped` is now reused like `ok`.
